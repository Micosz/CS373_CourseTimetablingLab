# Lab ขาดแคลน: 4 / 3 / 2 ห้อง (issue #13)

รันเมื่อ 2026-11-19 ด้วย engine C# ตาม [docs/protocol.md](../../docs/protocol.md) ข้อ 1 หลังล็อกพารามิเตอร์แล้ว รอบนี้รัน **ครบทั้ง 4 วิธี** ไม่ได้เลือกวิธีเดียว

```sh
python dataset_tools/make_lab_variants.py          # สร้าง data/variants/fall-cs-labs3.json.gz และ labs2
for n in 3 2; do
  dotnet run -c Release --no-build --project dotnet/src/Timetabling.Cli -- batch run --dataset data/variants/fall-cs-labs$n.json.gz \
    --methods greedy hc sa ga --room-modes weekly fixed --seeds 1001-1010 --budget 500 --workers 20 \
    --parameters experiments/tuning/selected-parameters.json --name "Lab scarcity: $n Labs (issue #13)" \
    --output experiments/lab-scarcity/labs$n
done
```

## อ่านผล

- **เมื่อเหลือ Lab 3 ห้อง โหมด weekly จัดไม่ครบทุกรันแล้ว (ที่งบ 500)** วิธีค้นหาจัดครบเพียง 1 ถึง 4 จาก 10 รัน และเหลือเฉลี่ย 1.5 ถึง 3.8 คาบ (มากสุด 7 คาบ) จึงพูดไม่ได้ว่าลด Lab ได้หนึ่งห้องโดยยังจัดครบ
- **เมื่อเหลือ 2 ห้อง ไม่มีรันไหนจัดครบ** วิธีค้นหาเหลือเฉลี่ย 32 ถึง 40 คาบ Greedy เหลือ 126 คาบ
- **โหมด weekly เหลือคาบที่จัดไม่ได้น้อยกว่าโหมด fixed มากในทุกจำนวน Lab** (3 ห้อง: ไม่เกิน 4 คาบ เทียบกับกว่า 500 คาบ) ข้อนี้เป็นผลของโจทย์ที่ตั้งไว้ เพราะในโหมด fixed คาบที่มีสัปดาห์ Lab ต้องอยู่ Lab ทั้งเทอม ไม่ใช่ข้อค้นพบเกี่ยวกับมหาวิทยาลัยจริง
- **ช่องว่างระหว่าง Greedy กับวิธีค้นหากว้างขึ้นเมื่อ Lab น้อยลง** 14 เทียบ 0 ที่ 4 ห้อง, 30 เทียบ 2 ถึง 4 ที่ 3 ห้อง และ 126 เทียบ 32 ถึง 40 ที่ 2 ห้อง

## อ่านอย่างระวัง

- ชั่วโมง "Lab ไม่จำเป็น" ของ fixed **ลดลง** เมื่อ Lab น้อยลง เพราะคาบที่จัดไม่ได้มากขึ้น ไม่ได้แปลว่าใช้ Lab ดีขึ้น ให้อ่านคู่กับคาบที่ยังจัดไม่ได้เสมอ
- งบ 500 เท่านั้น ที่ชุดหลักทุกรันจัดครบตั้งแต่งบ 1,000 ([convergence](../convergence/README.md)) แต่ยังไม่ได้ลองงบมากขึ้นกับชุด 3 และ 2 ห้อง จึงยังไม่รู้ว่า 3 ห้องจะจัดครบได้หรือไม่เมื่อค้นหานานขึ้น
- เป็นการตัดห้องที่เล็กที่สุดออกแบบเดียว ไม่ได้ลองทุกชุดของห้องที่เหลือ ใช้ 10 seeds ต่อกรณีตาม protocol และยังไม่ได้ทดสอบสถิติระหว่างวิธีในชุดนี้
- ความต้องการ Lab เป็นข้อมูลจำลอง (assumption A10)
