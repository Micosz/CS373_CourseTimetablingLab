# Experiment protocol (Final Project)

กติกานี้กำหนดไว้ **ก่อน** เริ่มจูนและรันการทดลองสุดท้าย (issue #4) ผลใน `experiments/` ทุกชุดหลังจากนี้ต้องทำตามเอกสารนี้ ถ้าต้องเบี่ยงจากกติกาให้บันทึกเหตุผลไว้ใน README ของชุดผลนั้น ไม่แก้เอกสารนี้ย้อนหลัง

## 1. ชุด seed (ไม่ซ้ำกัน)

| ใช้ทำอะไร | Seeds | หมายเหตุ |
|---|---|---|
| จูนพารามิเตอร์ (#5) | 1–10 | ใช้ **เฉพาะ** ตอนเลือกพารามิเตอร์ |
| ทดสอบ / การทดลองสุดท้าย (#6) | 1001–1030 | ไม่ถูกใช้ตอนจูนเลย |
| ศึกษางบ (#8) และ Lab ขาดแคลน (#13) | 1001–1010 | ส่วนหนึ่งของชุดทดสอบ ใช้หลังพารามิเตอร์ถูกล็อกแล้ว |

Seed สร้างข้อมูล (`20261027`) แยกจาก seed ค้นหาคำตอบเหมือนเดิม

## 2. งบเท่ากันทุกวิธี

- **500 evaluations ต่อรัน** สำหรับ HC, SA และ GA นับทุกครั้งที่ decoder ประเมินคำตอบ รวมคำตอบเริ่มต้น การ calibrate อุณหภูมิของ SA และประชากรเริ่มต้นของ GA
- Greedy เป็น baseline แบบ constructive ใช้ 1 evaluation ตามนิยาม (คำตอบเริ่มต้นเดียวกับที่อีกสามวิธีเริ่มจาก) และให้ผลเท่ากันทุก seed
- **Time cap 3,600 วินาทีต่อรัน** หลวมกว่าเวลาที่คาดราว 20 เท่า (ราว 75 วินาทีต่อรันที่ 0.15 วินาทีต่อการประเมิน) ถ้ามีรันใดจบด้วย `time_limit` ถือว่าชุดผลนั้นใช้ไม่ได้ ต้องรันใหม่ด้วยจำนวน process ที่น้อยลง
- ทุกวิธีใช้ genome, decoder, ตัวตรวจ และ initial genome ชุดเดียวกัน

## 3. Metric

**Metric หลัก** เทียบแบบ lexicographic ตามลำดับเดิมของโปรเจกต์ ค่าทั้งหมดนับใหม่โดยตัวตรวจอิสระ (`solution_validator.py`):

1. คาบรายสัปดาห์ที่ยังจัดไม่ได้ (น้อยดี)
2. นาทีที่ Computer Lab ถูกใช้ในสัปดาห์ที่ไม่ต้องใช้ Lab (รายงานเป็นชั่วโมง, น้อยดี)
3. จำนวนครั้งที่เปลี่ยนห้องข้ามสัปดาห์ (น้อยดี)

เมื่อต้องการตัวเลขเดียว ใช้ `energy` ของ engine ซึ่งคงลำดับ lexicographic ไว้ (มี test ยืนยันใน `engine/tests/test_engine.py`)

**Metric รอง:** success rate (สัดส่วนรันที่จัดครบทุกคาบ, unassigned = 0), เวลาค้นหา (วินาที), และจำนวนเปลี่ยนห้องเทียบกับ lower bound (#10)

รันที่ไม่ผ่านตัวตรวจ (hard violations > 0) หรือจบด้วย `error` / `time_limit` นับเป็นรันที่ล้มเหลว รายงานแยก และไม่ตัดทิ้งเงียบ ๆ

## 4. สถิติ (กำหนดล่วงหน้า, α = 0.05)

ใช้ข้อมูลโหมด weekly บน seed ทดสอบ 30 ตัว แต่ละ seed เป็นหนึ่ง block

1. **Friedman test** เทียบ 4 วิธีพร้อมกัน จัดอันดับภายในแต่ละ seed ตาม metric หลักแบบ lexicographic (ค่าเท่ากันได้อันดับเฉลี่ย) ใช้สถิติ chi-square พร้อม tie correction, df = 3
2. ถ้า Friedman มีนัยสำคัญ ทำ **Wilcoxon signed-rank แบบจับคู่ two-sided** ทุกคู่ (6 คู่) บนค่า `energy` ตัดคู่ที่เท่ากันออก ใช้อันดับเฉลี่ยเมื่อมีค่าซ้ำ และใช้ normal approximation พร้อม tie correction และ continuity correction แล้วปรับ p-value ด้วย **Holm** ทั้ง 6 คู่
3. รายงานคู่ละ: จำนวน seed ที่วิธีหนึ่งชนะ/เสมอ/แพ้ และค่ามัธยฐานของผลต่างของแต่ละ metric เพื่อให้อ่านขนาดผลได้ ไม่ใช่แค่ p-value
4. **Weekly เทียบ fixed** (#3): ต่อวิธี ใช้ Wilcoxon แบบจับคู่ตาม seed บนชั่วโมง Lab ที่ไม่จำเป็นและคาบที่ยังจัดไม่ได้ ปรับ Holm ภายในแต่ละ metric

สถิติทั้งหมดคำนวณโดย `engine/analyze.py` ด้วย standard library เท่านั้น และมี test เทียบกับค่าที่คำนวณมือ

## 5. การจูน (#5)

- จูนในโหมด weekly บน seed 1–10 ด้วยงบ 500 เท่ากับการทดลองสุดท้าย
- HC: `restart_patience` ∈ {5, 10, 20, 50, 100, 200, 500}
- SA: `initial_acceptance` ∈ {0.2, 0.5, 0.8, 0.95} × `cooling_rate` ∈ {0.9, 0.97, 0.99, 0.995, 0.999}
- GA: ค่าเริ่มต้น + random search 19 ชุด (seed ของการสุ่มชุดค่า = 4) จาก `population_size` 6–40, `mutation_rate` 0.1–1.0, `crossover_rate` 0.5–1.0, `tournament_size` 2–5 (ไม่เกินประชากร), `elites` 1–3
- **เกณฑ์เลือก:** ค่าเฉลี่ยบน seed จูนของ (คาบที่ยังจัดไม่ได้, นาที Lab ไม่จำเป็น, เปลี่ยนห้อง) เทียบแบบ lexicographic ถ้าเท่ากันเลือกค่าเริ่มต้น
- ทุกชุดค่าที่ลองและผลดิบถูก commit ใน `experiments/tuning/` ไฟล์ที่เลือกคือ `experiments/tuning/selected-parameters.json` (อ่านได้ด้วย `--parameters`)
- โหมด fixed ใช้พารามิเตอร์ชุดเดียวกับ weekly (ไม่จูนแยก) เพื่อให้ผลต่างมาจากนโยบายห้องอย่างเดียว
